# 0.62.0
## Features Added
  - Boards (experimental): a board reads topic data, metrics and entities (events, sessions, devices, datasets, collections and files) and uses the relationships Roboto records between them to combine kinds of data, such as a vehicle's path on a map beside a table of the vehicle's events, or speed grouped by each session's software version. With `roboto.experimental.boards.Board`, you can create, load, list, update and delete the boards you see in the Roboto web app, and share them with your organization. A `BoardDefinition` describes a board's panels and the data they show, and its `calendar` sets the time zone the board shows its times in and the day its weeks start on. Contact Roboto to enable Boards for your organization.
  - `Metric.aggregate` takes `time_zone` and `week_start`, so its periods start at midnight in the time zone you name and its weeks start on the day you name, for example `time_zone="America/Los_Angeles"` and `week_start=DayOfWeek.Sunday`. Import `DayOfWeek` from `roboto.domain.metrics`. The defaults, UTC and Monday, keep existing aggregations unchanged. Name a time zone by area and location, such as `"Europe/Paris"`; abbreviations such as `CET` are refused.
  - RoboQL device queries can sort by `device_type_id`, which orders devices by their device type's ID, not its name. Devices without a device type come last in an ascending sort and first in a descending one.
  - `roboto auth login` signs the CLI in through your browser and saves an access token to your Roboto config file, so you don't have to create a token in the web app and add it to the file by hand. Check that the page it opens shows the confirmation code printed in your terminal, then click Approve. Over SSH, on Linux without a display, or with `--no-browser`, open the printed link on any device instead, approve there, and paste the code the page then shows into your terminal. The token lasts 30 days unless you pass `--expiry-days`, up to 365, and appears under Settings > Tokens as `CLI sign-in (<hostname>)`. To sign in to a profile other than the one the CLI uses by default, run `roboto --profile <name> auth login`. To replace the token in an existing profile, add `--overwrite`; the old token keeps working until it expires or you delete it.
  - `roboto setup` offers to sign you in through your browser, as `roboto auth login` does, when it finds no access token or Roboto rejects yours, instead of asking you to paste a token from the web app. A token from setup lasts 180 days unless you pass `--expiry-days`, up to 365. When `ROBOTO_API_KEY` or `ROBOTO_BEARER_TOKEN` is set, setup checks that token and never offers to sign in.

## Bugs Fixed
  - With `ROBOTO_PROFILE` set to an empty value, `roboto setup` could save the organization you chose to a different profile from the one holding your access token. It now saves the organization to that profile.
  - `AgentThread.run` waits for the results of tools that run in Roboto or in another program connected to the same thread. When those were the only tools the AI was waiting on, `run` let the AI continue without their results.
